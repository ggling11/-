# 인수인계 — 새 세션은 이것부터 읽기

이 저장소는 **쿼터뷰 듀오 보스 액션 게임(가제)**의 기획과 프로토타입이다.
새 세션은 이 문서 → `docs/기획서.md` → `prototype/index.html` 순서로 읽고 시작한다.

---

## 1. 지금까지 확정된 것 (바꾸려면 사용자에게 먼저 물어볼 것)

- **장르**: 3D 툰 렌더링, 쿼터뷰 고정 카메라, 보스 공략 액션
- **모드**: 혼자 하면 태그 액션(젠레스 존 제로, 명조), 둘이 하면 로컬 2인으로 각자 이동
- **레퍼런스**: 엘든 링 밤의 통치자(보스 공략), 젠존제/명조(태그)
- **복식은 감정 레퍼런스다.** 공, 네트, 랠리, 코트 같은 형태는 절대 가져오지 않는다.
- **감정 우선순위**
  1. 합이 맞는 쾌감 (최우선)
  2. 등을 맡기는 신뢰
  3. "내 거 / 네 거" 순간 판단
  4. 나머지 (찬스 만들고 끝내 주기, 역할 교대, 실수 메워 주기)
- **핵심 메커니즘 "받기와 틈"**: 한 명이 보스 공격을 받아내면, 보스의 틈은 파트너 쪽(반대편)으로 열린다. 파트너가 틈을 치면 **합**, 받기와 거의 동시에 치면 **완벽한 합**.
  - 받은 사람은 반동으로 못 친다. 규칙이 아니라 몸과 공간이 이유가 되게 한다.
  - 둘 다 받으면 칠 사람이 없어서 틈이 날아간다. 벌칙이 아니라 아쉬움으로 느끼게 한다.
  - 완벽한 합을 노리려면 파트너는 받기 성공을 보기 전에 휘둘러야 한다. 이게 곧 신뢰다.
  - 합을 친 사람에게 보스 시선이 넘어가서 역할이 저절로 교대된다.
- 자세한 내용과 수치는 `docs/기획서.md`에 있다.

## 2. 아직 정해지지 않은 것

- "맛있는 액션게임이면서 동시에 ___" — 사용자의 끊긴 문장. 아직 답을 못 들었다.
- 캐릭터 수 (2명 고정 vs 로스터에서 2명 선택)
- 게임 구조 (보스 러시 / 원정형 / 스테이지형)
- 캐릭터별 강점 (안 C, 보류 중)
- **"와" 소리가 나오는지는 아직 아무도 확인 못 했다.** 사용자가 모바일이라 직접 플레이를 못 했다.

## 3. 프로토타입 현황 (`prototype/index.html`)

- 게시 링크: https://claude.ai/artifact/MQX4nvqw2vcw21cWZmLJfY (원본. 사용자가 시키지 않으면 덮어쓰지 말 것)
- Three.js 0.160.0 + lil-gui 0.19.2, jsdelivr import map. 파일 하나에 다 있다.
- **모드 3개**: 혼자 하기(태그), 둘이 하기(로컬 2인), 혼자 듀오 연습(둘 다 필드, Q로 조작만 넘김)
- **보스 공격 4종**: 내려찍기, 돌진(받기 가능, 주황), 충격파(받기 불가, 보라), 사이 내려찍기(듀오만)
- **조정 패널**: 게임 중 ` 키. 판정, 틈 길이, 배율, 히트스톱, 아트 스타일 3종(기본 툰/파스텔/강한 대비)
- **테스트용 설정 (사용자 요청)**: 틈 길이 3.0/2.0초, 약점 피격 거리 +1.6, 틈 범위 ±130°, 아군 피 무한. 기획서 초기값은 코드 주석에 남겨 둠.
- 조작: 1P `WASD F(공격) G(받기) Space(회피) Q(태그)`, 2P `방향키 K L J I`, 게임패드 지원. **터치 조작은 아직 없다.**
- 코드 구조: `CFG`(조정값) → 렌더러/씬 → 효과·효과음(WebAudio 합성) → 입력 → `Player` → `Boss` → 전투 규칙(`openGap`, `doHap`, `playerHitsBoss`, `bossHitsPlayer`) → 화면 흐름 → 그리기
- 테스트 핸들: `window.__game`

## 4. 작업 규칙

- **브랜치**: 세션마다 자기 브랜치에서 작업한다. 다른 세션의 브랜치에 푸시하지 않는다.
- **아티팩트**: 탐색용 결과물은 **새 링크로 따로 게시**한다. 원본 링크는 사용자가 시킬 때만 업데이트한다.
- **결정 기록**: 새로 정한 것, 바꾼 것은 `docs/기획서.md`에 남긴다. 세션 고유의 실험은 `docs/실험/<주제>.md`에 남긴다.
- **아티팩트 파일 형식**: `<!doctype>`, `<html>`, `<head>`, `<body>` 없이 바로 `<title>`부터 쓴다. 게시할 때 뼈대가 씌워진다.
  - CSS에 `[hidden] { display: none !important; }`가 있어야 오버레이가 숨겨진다. 지우지 말 것.
  - 외부 스크립트는 jsdelivr/cdnjs/unpkg만 된다.
- **검증**: 클라우드 컨테이너에서는 CDN이 막혀 있다. 아래 스모크 테스트를 돌린다.
  ```
  cd prototype/test && npm install && node smoke.mjs
  ```
  헤드리스 크로미움은 프레임이 매우 느리다. 타이밍 체감은 테스트로 확인할 수 없으니, 손맛은 사용자에게 물어볼 것.
- **사용자**: 한국어로 대화한다. 지금은 주로 모바일로 접속한다.

## 5. 세션별 시작 프롬프트

새 세션을 만들 때 아래 중 하나를 첫 메시지로 붙여 넣는다. 모든 세션 공통으로 맨 앞에 이 줄을 넣는다.

> `docs/인수인계.md`를 먼저 읽고, 확정된 것은 지키면서 아래 주제를 네 방식대로 창의적으로 발전시켜 줘. 결과는 새 아티팩트 링크로 보여주고, 정한 것은 `docs/실험/` 아래에 문서로 남겨 줘.

### A. 모바일 터치 조작
> 주제: 폰에서 프로토타입을 플레이할 수 있게 터치 조작을 붙여 줘. 가상 스틱과 공격·받기(누르고 있기)·회피·태그 버튼. 받기 타이밍이 터치에서도 정확하게 느껴져야 해. 혼자 듀오 연습 모드도 터치로 할 수 있게.

### B. "와"를 만드는 합 연출
> 주제: 완벽한 합이 터지는 순간을 최대한 "와" 소리 나게 만들어 줘. 히트스톱, 카메라, 슬로모션, 사운드, 툰 이펙트, 화면 연출. 합과 완벽한 합의 차이가 확실히 느껴지게.

### C. 보스 디자인
> 주제: 밤의 통치자처럼 크고 읽히는 보스를 2~3종 설계하고 하나 이상 구현해 줘. "받기와 틈" 규칙 위에서 사이 공격, 연속 공격, 후반 동시 공격(둘 다 받아야 열리는 틈)을 써서 감정 우선순위가 살아나게.

### D. 아트 스타일 탐색
> 주제: 3D 툰 렌더링 아트 스타일을 여러 방향으로 뽑아서 같은 장면으로 비교할 수 있게 해 줘. 셰이더, 외곽선, 팔레트, 아레나 분위기, 캐릭터 실루엣. 이미지 생성은 못 하니 코드로 만들 수 있는 범위에서.

### E. 캐릭터와 태그 연계
> 주제: 캐릭터 설계를 해 줘. 캐릭터마다 받기와 치기에서 다른 강점(기획서의 안 C), 솔로 태그 연계기, 듀오에서의 역할 차이. 기획 문서로 먼저 정리하고, 가능하면 프로토타입에 두 캐릭터를 차별화해서 넣어 줘.

### F. 게임 구조와 세계관
> 주제: 보스 러시 / 원정형 / 스테이지형 중 이 게임에 맞는 구조를 제안하고, 세계관과 톤을 잡아 줘. 감정 우선순위와 "받기와 틈"이 반복 플레이에서도 살아남는 구조여야 해. 코드보다 기획 문서 중심으로.

## 6. 결과 합치기

- 각 세션의 결과는 자기 브랜치와 자기 아티팩트 링크에 남는다.
- 마음에 드는 결과가 생기면, 한 세션에 "브랜치 `claude/...`의 ○○ 변경을 가져와서 합쳐 줘"라고 시킨다.
- 여러 세션이 같은 파일(`prototype/index.html`)을 크게 고치면 합칠 때 충돌이 난다. 합칠 때는 한 세션에서 하나씩 가져온다.
