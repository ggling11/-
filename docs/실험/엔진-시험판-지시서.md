# 엔진 시험판 — 자기 프롬프트와 검수 기준

> 사용자 결정 (10월 24일): "지금 html은 무거우니까" 유니티나 다른 도구를 설치하지 않고 Claude가 만들어 **exe로** 전달한다.
> - 순서: **시험 exe부터**. PC에서 켜지는지, FPS, 두 명 입력을 확인한 뒤에 게임을 옮기기 시작한다.
> - 받는 곳: **이 대화에 파일로**
> - PC: **데스크톱 + 외장 그래픽**
> - 입력: **"게임 패드 + 키보드, 게임 패드 + 게임패드 둘 다 가능하게 ← 중요"**
>
> 엔진: **Godot 4.7.2-stable** (표준판, .NET 아님). 이 컨테이너에서 편집기 화면 없이 Windows exe를 만들 수 있음을 확인했다(6장).
> 이 문서는 작업에 들어갈 때 다시 읽는 작업 지시서다. 통과 기준을 숫자로 재고, 통과하지 못하면 넘어가지 않는다.

---

## 0. 목표

시험판 하나로 사용자 PC에서 세 가지를 확인한다.

1. **켜진다.** Vulkan → D3D12 → OpenGL 순서로 자동 대체되고, 어느 드라이버로 켜졌는지 화면에 보인다.
2. **얼마나 빠른가.** 모비드 메탈 무대와 비슷한 부하에서 품질 4단계를 자동으로 재고, 결과를 복사해서 대화에 붙여 넣을 수 있다.
3. **두 명 입력.** 패드+키보드, 패드+패드가 반드시 된다. 키보드 하나를 둘이 나눠 쓰는 것(지금 HTML 방식)도 된다. 패드 연결이 끊겼다 다시 이어져도 같은 칸으로 돌아온다.

게임 규칙(받기·틈·합)은 아직 옮기지 않는다. 캐릭터는 대역(기본 도형)이고, 모델은 나중에 바꾼다.

## 1. 공통 규칙

1. **위치.** 프로젝트는 `godot/hap_test/` 아래 텍스트 파일(.godot, .tscn, .tres, .gd, .cfg)로만 만든다. 빌드 결과물(exe, pck, zip)과 내려받은 원본은 저장소 밖(작업용 임시 폴더)에 둔다. `godot/hap_test/.godot/`은 커밋하지 않는다.
2. **API는 추측하지 않는다.** 4.7.2의 실제 클래스 문서를 `godot --headless --doctool <폴더>`로 뽑아서 확인한다.
3. **화면 글자는 한글.** Godot 기본 글꼴에는 한글이 없으므로 글꼴을 묶는다. 제목은 Black Han Sans, 본문은 IBM Plex Sans KR (둘 다 OFL, 라이선스 파일을 함께 넣는다). 프로토타입과 같은 글꼴이다.
4. **외부 에셋은 CC0만** (ambientCG, Poly Haven). 저장소 크기를 아끼려고 1K 해상도. 출처 목록 파일을 둔다.
5. **크기와 카메라는 프로토타입과 같게.** 아레나 반지름 14, 플레이어 반지름 0.5, 이동 속도 6.2, 카메라 세로 시야 38°, 카메라 위치 = 바라보는 점 + (13, 16, 13). 그래야 측정한 부하가 실제 게임과 같은 화면 크기에서 나온다.
6. **색 규칙.** 1P 주황, 2P 파랑, 보스 붉은 네온. 금색은 합 전용이라 시험판 UI 강조색으로 쓰지 않는다.
7. **섬광은 0.1초 안에 가라앉는다** (기존 기준).
8. **원본은 건드리지 않는다.** `prototype/`과 다른 문서는 바꾸지 않는다. 이 지시서와 `godot/` 폴더만 만든다.

## 2. 만들 것

### 2.1 무대 — 부하가 실제 게임과 비슷해야 측정이 의미 있다

- **노을 마당:**
  - 판석 바닥(CC0 PBR 질감: 색, 노멀, 거칠기), 바깥 판석, 돌난간 기둥
  - 석등 4개(OmniLight3D), 쇠 바닥판, 흩어진 장갑 조각, 바위, 나무 몇 그루(단순 도형 가능)
  - 바닥 낙엽 1,500장과 풀 900포기(MultiMesh), 떨어지는 잎 70장(셰이더 또는 GPUParticles3D), 빛줄기 몇 줄(투명 판)
  - 노을 하늘과 노을 안개. 해는 보스 너머 오른쪽 위 약 33°, 따뜻한 역광.
- **나눠 두기.** 정적 배경을 거대한 덩어리 하나로 합치지 않는다. HTML에서는 합친 덩어리 때문에 그림자와 화면 컬링이 전혀 되지 않았다.
- **캐릭터 대역 3개** (기본 도형 조합, StandardMaterial3D):
  - 재질은 흰 세라믹 장갑(clearcoat), 검은 금속 골격, 발광 네온. 모두 그림자를 드리운다.
  - 보스: 앞으로 숙인 덩치, 붉은 네온.
  - 1P 모루: 넓은 챙 투구, 주황 네온.
  - 2P 제비: 가늘고 긴 몸, 파랑 네온.
- **이펙트 부하:** 합이 터지는 순간을 흉내 낸다.
  - GPUParticles3D로 불티, 먼지, 사각 데이터 조각을 낸다.
  - 짧은 섬광 조명과 충격파 고리를 더한다.
  - 측정 중에는 2초마다 터진다.
- **후처리:** 블룸(glow), ACES 톤 매핑, 안개, SSAO. 높은 단계에서는 볼류메트릭 안개와 가벼운 화면 셰이더(색 갈라짐, 필름 그레인)를 더한다.

### 2.2 품질 단계 4개

`1`~`4` 키와 패드 십자키 좌우로 바꾼다. 아래는 출발점이고, 실제로 적용한 값은 정보 막대와 결과 텍스트에 그대로 적는다.

|---|---|---|---|---|
| 3D 렌더 배율 | 0.67 (FSR) | 0.85 (FSR) | 1.0 | 1.0 |
| 안티에일리어싱 | FXAA | FXAA | MSAA 2x 또는 TAA | MSAA 4x |
| 해 그림자 | 1024, 30m | 2048, 40m | 4096, 50m | 4096, 60m, 부드럽게 |
| SSAO | 끔 | 낮음 | 켬 | 높음 |
| 볼류메트릭 안개 | 끔 | 끔 | 켬 | 켬 |
| 석등 그림자 | 끔 | 끔 | 끔 | 켬 |
| 풀·낙엽 | 절반 | 전부 | 전부 | 전부 |
| 화면 셰이더 | 끔 | 끔 | 켬 | 켬 |

### 2.3 화면과 흐름

- **창:** 전체 화면(모니터 해상도)으로 시작한다. `F11`과 `Alt+Enter`로 창 모드와 전환한다.
- **타이틀「합 · 시험판」:**
  - 고를 것: [성능 측정] [두 명 입력 시험] [자유롭게 보기] [끝내기]
  - 마우스, 키보드(↑↓·Enter), 패드(십자키·A) 어느 것으로든 고른다.
- **정보 막대** (늘 보이고, `F1`로 숨긴다): FPS, 프레임 시간(ms), 품질 단계, 그래픽 드라이버(Vulkan/D3D12/OpenGL), GPU 이름, 해상도와 렌더 배율, 수직 동기화.
- **성능 측정** (자동, 약 1분):
  - 수직 동기화는 끈다.
  - 4단계 × 12초씩 잰다. 앞 2초는 데우기라 빼고 잰다.
  - 장면은 매번 같다: 쿼터뷰 고정 카메라, 보스가 2초마다 내려찍고 이펙트가 터지며, 두 대역이 원을 그리며 돈다.
  - 단계마다 재는 것:
    - 평균 FPS, 1% 하위 FPS
    - 가장 긴 프레임(ms), 끊김 수(50ms 넘는 프레임)
    - 처음 5초 안의 끊김 수(셰이더 준비 때문에 생기는 끊김 확인용)
  - **결과 화면:**
    - 단계별 결과 표
    - 추천 단계: 평균 FPS가 모니터 주사율(최소 60) 이상이고 1% 하위가 45 이상인 가장 높은 단계
    - [결과 복사] (클립보드)
    - 결과 파일 저장: exe 옆 `hap_test_result.txt`, 안 되면 사용자 폴더. 저장한 경로를 화면에 보여 준다.
  - 결과 텍스트에는 다음을 넣는다: 시험판 버전, Godot 버전, OS, CPU 이름, GPU 이름, 드라이버, 해상도, 주사율, 단계별 실제 설정값.
- **두 명 입력 시험:**
  - **참가:** "쓸 장치에서 아무 버튼이나 누르세요"라고 띄운다. 누른 장치가 1P 칸, 2P 칸에 들어가고 장치 이름과 종류가 보인다.
  - **움직이기:** 참가하면 마당에서 대역을 움직인다.
  - **칸마다 보여 줄 것:** 실시간 입력(스틱 값, 트리거 값, 누른 버튼: 공격·받기·회피·태그), [진동 시험](패드만).
  - **참가 해제와 자리 바꾸기:** 참가 해제는 Back/Select 길게 또는 `Backspace`. 1P와 2P 자리도 바꿀 수 있다.
  - **연결이 끊기면:** 그 칸에 "연결 끊김 — 다시 연결하면 이어서"를 띄운다. 같은 패드가 다시 연결되면 같은 칸으로 돌아온다(가능하면 패드 고유값으로 알아본다).
- **자유롭게 보기:** 참가한 사람이 대역을 움직이고 공격 버튼으로 이펙트를 터뜨린다. 품질 단계를 바꿔 가며 FPS를 본다.
- **효과음:** 공격(타격), 받기(쇳소리), 합(화음), 메뉴 이동. 프로토타입의 합성음 성격을 흉내 내서 WAV로 미리 만든다. 소리가 나는지 확인하는 용도다.
- **나가기:** `Esc`나 Start를 누르면 타이틀로 돌아간다. 타이틀에서 `Esc`를 누르면 끝내기를 확인한다.

### 2.4 입력 규칙 (중요)

- **장치를 알아보는 법:** 장치 = (종류, 번호)다. 키보드 이벤트와 0번 패드 이벤트는 번호가 둘 다 0일 수 있으니 반드시 이벤트 종류로 구분한다.
- **키보드는 두 구역이다** (프로토타입 키 배치 그대로):

| 구역 | 이동 | 공격 | 받기 | 회피 | 태그 |
|---|---|---|---|---|---|
| 왼쪽 (프로토타입 1P) | WASD | F | G | Space | Q |
| 오른쪽 (프로토타입 2P) | 방향키 | K · 숫자패드 1 | L · 숫자패드 2 | J · 숫자패드 0 | I · 숫자패드 3 |

  한 사람이 키보드를 쓰면, 그 사람이 처음 누른 구역이 그 사람 것이다. 그래서 패드+키보드, 패드+패드, 키보드 두 구역이 모두 된다.

- **패드 버튼** (프로토타입과 같은 뜻):

| 행동 | 버튼 |
|---|---|
| 공격 | X (서쪽) |
| 받기 | B (동쪽), RB, RT |
| 회피 | A (남쪽) |
| 태그 | Y (북쪽), LB |
| 이동 | 왼쪽 스틱 또는 십자키 (데드존 0.2, 원형) |

  트리거는 버튼이 아니라 축이다.
- **같은 모델 패드 두 개**도 번호로 따로 잡힌다.
- **한 장치는 한 칸에만** 들어간다. 두 칸이 다 차면 세 번째 장치는 참가하지 못한다.
- **연결과 끊김:** `Input.joy_connection_changed`로 처리한다.

### 2.5 내보내기와 묶음

- **내보내기 설정:**
  - Windows Desktop x86_64, exe와 pck는 따로(embed 끔)
  - 콘솔 래퍼 exe 포함(오류 확인용)
  - 아이콘과 파일 정보: 이름 "합 시험판", 버전 0.1.0
  - 셰이더 미리 굽기: Xvfb + lavapipe 아래에서 내보내야 실제로 구워진다. `--headless`로는 아무것도 굽지 않고 경고도 없다(6장).
  - 렌더링 드라이버: 기본 Vulkan, 대체 D3D12와 OpenGL 허용
- **압축 파일 `hap_test_v0.1.zip`에 넣을 것:**
  - `hap_test.exe`, `hap_test.console.exe`, `hap_test.pck`
  - `run_d3d12.bat`, `run_opengl.bat` (파일 이름과 내용은 영문)
  - `읽어주세요.txt`: 실행 방법, SmartScreen 안내("추가 정보 → 실행"), 결과 붙여 넣는 법, 문제가 생기면 콘솔 exe로 켜서 화면을 찍어 보내는 법, 로그 위치
  - 글꼴 라이선스, 에셋 출처

## 3. 검수 — 통과 기준

| 검사 | 통과 기준 |
|---|---|
| 정적 검사 | 모든 .gd 파싱 오류 0. headless 실행 로그에 오류 0 |
| 입력 자동 시험 (headless, 가짜 입력 이벤트) | 7가지 모두 통과, 종료 코드 0 (목록은 표 아래) |
| 성능 측정 빠른 실행 (Xvfb + lavapipe) | 끝까지 돌고, 결과 파일이 생기고, 형식이 맞다. 숫자는 소프트웨어 렌더링이라 의미 없음 |
| 스크린샷 (Xvfb + lavapipe, 1280×720) | 타이틀, 측정 중(낮음·최고), 결과 화면, 두 명 입력 화면이 모두 비어 있지 않다(휘도 표준편차 8 이상). 한글이 깨지지 않는다(눈으로 확인) |
| 섬광 | 이펙트 섬광이 0.1초 안에 가라앉는다 (연속 프레임 화면 평균 휘도) |
| 내보내기 | exe, 콘솔 exe, pck가 있다. PE32+ GUI다. pck에 Vulkan 셰이더 캐시가 들어 있다. zip 크기를 기록한다 |

입력 자동 시험 7가지:
1. 패드 0 + 키보드 왼쪽
2. 패드 0 + 패드 1
3. 키보드 왼쪽 + 키보드 오른쪽
4. 키보드 이벤트(번호 0)가 패드 0 칸을 건드리지 않는다
5. 패드가 끊겼다 다시 연결되면 같은 칸으로 돌아온다
6. 세 번째 장치는 참가하지 못한다
7. 대각선 이동 크기가 1을 넘지 않는다

## 6. 점검 기록 (10월 24일) — 이 방향을 고른 근거

에이전트 다섯이 나눠서 실제로 만들어 보고 재 봤다. 검토 에이전트 하나가 결과를 다시 확인했다.

- **Godot (통과):**
  - 4.7.2-stable 편집기와 내보내기 템플릿을 받았다(체크섬 일치).
  - 손으로 쓴 3D 장면을 `--headless`로 Windows exe로 내보냈다. 5초, exe 109MB, zip 38MB, PE32+ GUI, wine 필요 없음.
  - 아이콘과 파일 정보도 rcedit 없이 들어간다.
  - Linux 빌드는 300프레임을 정상으로 돌았다.
  - Xvfb + lavapipe(CPU Vulkan)로 Forward+ 화면을 실제로 그려 스크린샷을 찍었다. 장당 0.7~0.95초라 느리지만 검수용으로는 된다.
  - 한글은 묶은 글꼴로 나온다. 뼈대와 애니메이션이 있는 glTF도 headless로 들여온다.
- **확인 못 한 것:**
  - exe가 실제 Windows에서 켜지는지(여기 wine에서는 시작하다 멈춘다. Rust로 만든 대조용 exe는 wine에서 돈다).
  - 실제 그래픽카드에서의 FPS. 그래서 시험판을 먼저 만든다.
- **안 고른 것:**
  - HTML을 Electron으로 감싸는 방법: 실제로 만들어 봤지만 151MB이고, 브라우저와 똑같은 그리기 경로라서(그리기 344회, 삼각형 13만 2천 개) 렉이 줄지 않는다.
  - Rust + Bevy: 도구 사슬은 되지만, 편집기와 파티클 등이 없어서 Godot보다 1.5~3배 손이 간다(추정).
- **HTML이 무거웠던 이유** (CPU 렌더러로 잰 상대값):
  - 픽셀당 비용이 크다: 고해상도, 4x MSAA HDR, 후처리 15회.
  - 매 프레임 다시 그리는 해 그림자: 그리기 347회 중 140회. 합친 배경 덩어리라 컬링이 안 된다.
  - 모든 픽셀에서 계산하는 점광원 5개.
  - 112조각 캐릭터.
  - 플레이 중 셰이더 컴파일 끊김.
- **Godot에서도 남는 비용:** 해상도에 비례하는 후처리, HDR MSAA, 큰 투명 겹침, 실시간 부드러운 그림자. 그래서 품질 단계와 렌더 배율을 처음부터 넣는다.
- **주의할 점:**
  - 셰이더 미리 굽기는 Xvfb + lavapipe일 때만 Vulkan 캐시가 생긴다. D3D12로 대체되는 PC는 미리 구운 셰이더가 없다.
  - LightmapGI 굽기는 편집기 화면을 띄우는 우회로만 된다. 시험판에서는 쓰지 않는다.
